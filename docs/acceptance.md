# 验收清单（E 维护）

## 第一次联调：跑通链路

- [ ] 输入聊天 → 后端收到 → 页面显示示例分析结果
- [ ] 后端 `/health` 返回 `{"status": "ok"}`
- [ ] 页面显示的分析结果带 `is_sample` 标记（说明用的是开发样例）

## 第二次联调：真实模型

- [ ] 输入聊天 → 调用真实模型 → 页面显示真实分析结果
- [ ] 模型失败时页面给出明确错误提示，不是空白
- [ ] 结果字段与 docs/api.md 完全一致

## 第三次联调：编辑与留存

- [ ] 修改结果 → 保存 → 刷新 → 重新打开 → 导出
- [ ] 修改后刷新页面，内容与保存时一致
- [ ] 导出的 JSON 能被文本编辑器正常打开，中文不乱码

## 演示前检查

- [ ] 换一台电脑能从 README 的步骤启动成功
- [ ] 页面、导出、错误提示正常
- [ ] 演示脚本和试用结果里的数据只写实际测得的
- [ ] 保留已保存案例作为备用时，演示中明确说明是历史结果

## 问题分配

| 现象 | 优先负责人 |
| --- | --- |
| 按钮、页面显示或编辑异常 | A 或 B |
| 请求失败、保存失败、记录丢失 | C |
| 内容乱编、字段缺失、结果无法解析 | D |
| 操作流程不清楚、验收要求不一致 | E 确认后同步全组 |

暂时无法定位时，由 C 查看完整请求流程，再确定负责人。

报问题必须附上：**输入内容、操作步骤、实际结果、预期结果**。

> 例：输入“数量从 100 件改为 150 件”，结果仍显示 100 件；预期识别最终数量 150 件。附原始聊天和结果截图。
