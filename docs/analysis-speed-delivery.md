# 分析提速与实际验收

日期：2026-10-20。输入均为虚构商务聊天，测试使用临时账号和数据库，不读取真实用户对话。正式模型仍为 gpt-6.1-sol、medium，未更换服务、凭据或关闭质量复核。

## 交付结果与边界

1. 固定文字演示保留23轮、46句，固定截图保留原图，使用经过核对和严格校验的预置结果。浏览器从提交到完整结果显示分别为119ms、140ms；不是云端模型变快了，而是明确选择了演示结果。
2. 同一账号短时间内重复同一真实输入可复用已校验结果。一次真实短对话首次73.278秒、立即重复51.022ms，约减少99.930%的等待。两次公开结果除新记录编号外逐项一致。
3. 首次新聊天仍受当前云端服务响应影响。长文本和截图中途验证达到90秒上限，**未达到首次真实分析稳定快速的目标**。不能用演示或缓存数据冒充首次云端速度，也不能给出可信的首次分析提速百分比。

## 实施的优化

### 固定演示直接给出经过校验的结果

- `ChatInput.vue` 只有按钮原样填入且未修改时发送 `X-Keyoushu-Demo: 1`；填充按钮和快捷键继续保留。
- 后端不能只相信这个标记：文字必须逐字匹配版本内样例，图片必须匹配固定SHA256，附加文字/客户名称也必须匹配。修改内容、图片字节或客户名称后即不命中。
- 图片表单传输的CRLF仅作传输换行规范化，不对用户文本作模糊匹配。
- 结果明确标注“演示结果”“本次未调用云端分析”，来源标记保存为 `is_sample=true`，不能通过编辑伪装为真实分析。
- 仍经过AIOutput及原文来源校验，并保存历史、原图和转录；可以编辑、导出、采纳建议、加入日历。演示画像不写入“我的客户”。
- 固定日期保留原文；截图的模糊/相对日期按业务参考日期推算，并关联待确认问题。界面说明固定日期应以原文为准。

预置内容是公开虚构素材，不是用户数据缓存。后端自验请求文字54.512ms、截图62.964ms，其中保存约11–13ms；浏览器完整显示119/140ms。此前文字失败和截图超时并非成功完成时间，因此不计算“云端提速百分比”。

### 避免不必要的客户识别调用

已有明确客户画像时，继续先核对本次客户身份，并只读当前账号的匹配画像。

当前账号没有可匹配的明确画像时，没有旧资料可读，直接在完整分析及独立复核中识别客户，再核对姓名/公司确实来自客户原文，仍保存当前画像和快照。普通文字从3次云端调用降为2次，截图从4次降为3次。若并发分析期间出现了同一客户，则使用新画像重新整理，不覆盖新资料。

单独身份识别只发送可核对的客户发言，排除商家发言和界面名称；没有客户发言时直接返回未知，不猜测。保留严格类型、原文核对与一次修复重试。

### 独立复核只返回修正内容

原流程复核每次都重新输出完整七字段，哪怕全部正确。本次仍把全部原文、候选和旧画像发给独立复核，要求逐项检查角色、改口、遗漏、日期、关联问题、回复承诺及画像；只改变内部复核的返回方式：

```json
{
  "approved": true,
  "requirements": null,
  "questions": null,
  "tasks": null,
  "reply": null,
  "ddl_tasks": null,
  "suggested_tasks": null,
  "customer_profile": null
}
```

有错误时 `approved=false`，需要修正的字段输出完整替换值。`null` 是保留；`[]`/`""` 是清空。跨字段修改仍须满足完整AIOutput及关联日期校验。此结构仅用于内部复核，**用户收到的JSON字段与结构没有改变**。

复核格式/校验失败，只重试复核一次，不重新生成已经取得的完整草稿；草稿本身有结构错误仍重试草稿一次。复核超时/错误不冒充成功结果，模型错误继续透传。最终结果仍完整校验后才入库。

提示词同时要求精炼表达、保留必要原文和全部业务事项，不删字段、不省略否定、范围、依赖和待确认语气。

### 账号隔离的短时内存复用

- 仅复用成功且已事务保存的分析；命中后重新进行Pydantic及任务来源校验，保存新记录/快照，不复用旧操作状态。
- 键包含数据库位置、账号、精确文本和图片摘要、业务日期、模型/服务/推理/复核设置、密钥摘要、提示词摘要，以及账号下全部画像的版本；任一变化即失效。
- 两分钟有效、最多16项、总计2MiB。只在本机服务内存中保存，不新增数据库表或磁盘缓存，不跨账号。
- 命中时仍受实时登录/权限检查和画像版本保护；删除/更新画像会使旧键失效。可用 `FOLLOWUP_CACHE_ENABLED=false` 关闭。
- 缓存失败不破坏已经成功保存的业务结果。缓存不会重用先前的“已采纳/已加入”按钮状态。

## 真实验证与未达标部分

中途优化后的23轮文字仍在90秒等待首次模型结果；截图在90秒时仍处于复核（期间曾发生一次修复）。此后已修正复核提示词的输出要求冲突，并改为仅重试复核；未再次无限重复长样例。

临时 `low` 推理对照同样达到90秒，未获得更快且质量等同的证据，**因此没有采用low，正式.env未变更**。该实验也不是成功性能样本。

最终版本另用4句、118字的虚构商务对话验证真实分析和立即重复请求：

| 阶段 | 首次真实分析 | 立即重复 |
|---|---:|---:|
| 完整分析云端调用 | 25.873秒 | 0次 |
| 独立复核云端调用 | 47.312秒，approved=true | 0次 |
| 事务保存 | 16.110ms | 仍进行保存及校验 |
| 完整响应 | 73.278秒 | 51.022ms |

人工核对实际结果：保留150件、纯棉、6000元、2026-11-20、主管审批；将产能与交期可行性放入待确认，不擅自承诺；提取竞品比较信号为建议。生成客户画像并保存。重复响应除新编号外完全相同。证据：`final-real-short.json` 与 `final-real-short-repeat.json`。

这证明复用路径有效、最终复核协议真实跑通；**不能证明首次新长对话/截图已达到正常等待时间**。当前剩余耗时主要在云端等待，不在本机持久化。没有通过取消复核、放宽校验、异步丢画像或更换未授权模型掩盖问题。

本次未增加流式结果展示：用户看到的是完整且已核对的结果，没有把未通过复核的半成品当成最终结果。因此不提供“真实分析第一个字”的提速指标。没有删除功能，不需要执行可砍清单。
