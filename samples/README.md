# 演示与测试样例（E 负责）

每个样例一对文件：

| 文件 | 说明 |
| --- | --- |
| `chat-001.txt` | 输入：原始聊天记录 |
| `expected-001.json` | 预期结果：按 docs/api.md 的格式 |
| `acceptance-cases.json` | 文档五组输入及甲乙角色/单价场景；不是训练数据 |
| `screenshots/*.png` | 上述输入对应的合成聊天截图，用于实际本地 Qwen 图片验收；不是用户真实聊天 |

验收时按 `docs/acceptance.md` 的步骤操作，实际输出与预期文件对照。

预期结果检查语义与原文依据，不要求回复逐字相同。五组文档场景分别应保留100件/3000元/未给年份的10月30日前/设计要求、缺失信息追问、明确改为150件、约100件及3000–4000元区间、未最终确认的3000/5000预算歧义。甲乙场景中商家的问题与方案不作客户事实；40元左右是单件预算，下周保留原话并追问具体日期，不承诺交付。

写样例的要求：

- 数据只写实际测得或真实发生的，不要为了好看编造。
- 覆盖三种情况：信息明确、信息缺失（需要追问）、内容里有改口（例如数量从 100 改成 150）。
- 新增样例按 `chat-00N.txt` / `expected-00N.json` 顺序命名。
